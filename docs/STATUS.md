## What exists

A working local personal-use alpha using Python 3.12, Django 5.2, SQLite, server-rendered pages, and local media. Run start.cmd and open http://127.0.0.1:8000. Setup and checks are in README.md.

- Generation formats are three checkboxes: Basic Q/A, Cloze, and Basic + reverse. All seven nonempty combinations are supported; the old mixed setting still means Q/A plus cloze. Reverse cards are opt-in. Focus and manual note format remain visible radio options. Provider, model, and reasoning are dropdowns as requested. Legacy single-format POST clients remain supported. Empty/invalid format selections fail before generation.
- Basic + reverse creates two Anki cards from one note: front to back and back to front. Both sides must be nonempty and distinct. Generation guidance asks for short, unambiguous, source-supported pairs and permits an empty result when no suitable pair exists. Manual/editor previews show both directions, with escaped text and source crops. Note type stays fixed during edits to preserve Anki identities. Generation/JSON selection checks both prompts for exact duplicates (including swapped pairs) and exam/course logistics; existing edited reverse prompts are included in recent-question context. This does not provide semantic deduplication or convert existing notes into reverse cards.
- Four local CLI integrations: Codex, Claude Code, Gemini CLI, and Kimi Code, with separate connection/status/login/cancel routes under AI connections. Existing /codex/ links remain compatible. Claude uses its normal subscription sign-in and rejects detected API/custom-endpoint or Bedrock/Vertex/Foundry profiles without changing them. Login attempts are deduplicated, cancellable, and bounded to ten minutes; cancelling never invokes account logout.
- Gemini/Kimi use CLI-owned profiles under ~/.recalloom/cli/, outside lecture files. Users sign in once for Recalloom; no coding-profile credentials are read or copied. Their native/official npm CLI installations are supported, including the optional ignored data/clis/node_modules fallback. This installation has Gemini 0.59.0 and Kimi 0.42.0 installed there, with Node 24.16.0. The current Kimi package is TypeScript/Node; legacy Python Kimi is not supported. Both connections currently need user sign-in. Kimi's connection page offers CLI default/saved region, kimi.ai (Global), and kimi.com (Mainland China).
- Gemini/Kimi use bounded ACP JSON-RPC with cancellable stdin writes, output/deadline limits, session checks, disabled host file/terminal capabilities, restricted CLI settings, and no approved tools. Malformed/truncated output or tool attempts stop the batch without discarding earlier drafts. Gemini configuration avoids eager OAuth before ACP startup; GET status only reports a completed app sign-in marker and cannot establish token validity. Explicit Sign in again handles reconnection. Kimi uses official device login and ACP cached-login validation. Their CLIs can retain session history in the separate profile; lecture backups/deletion do not include/remove it. These restrictions are not an OS sandbox.
- Gemini models come from ACP session metadata; this checked version has no separate effort control, so reasoning stays disabled at CLI default. Kimi's managed models and per-model thinking settings are discovered after sign-in, including Off/On when reported. Custom Kimi providers are excluded. Selections survive retry/history/backups. Authenticated model discovery, completed real login, and inference for both are still unverified; no synthetic catalog is presented as an actual account catalog.
- Model capabilities come from installed CLI metadata: Codex app-server model/list, and Claude's SDK-compatible stream-JSON initialize handshake. No prompt or model turn is sent for discovery. Bounded native subprocesses reject host action requests. Only sanitized model IDs/labels/efforts and refresh time are cached in ignored data/models-*.json; account details and authentication output are discarded. Missing caches trigger discovery, and Refresh models updates them after CLI/account changes. Installed CLI metadata is not proof of account entitlement.
- Provider/model/effort selections are validated and retained with runs, retry, history, and backups. The browser filters efforts for each model and disables the selector for models without effort control. Provider changes clear sharing consent. Claude generation uses saved login, safe mode, disabled hooks/custom settings/memory/normal tools, empty MCP configuration, bounded stdin/output, cancellation/timeouts, and existing JSON/source validation. It never falls back to Codex after failure. Actual Claude login/inference is still pending; metadata discovery was verified without inference. See docs/CLI_PROVIDERS.md for implementation details and Gemini/Kimi/DeepSeek/Qwen research.
- Delete set is available in the library and lecture header. A separate confirmation page includes counts, a backup download, and a required confirmation tick. CSRF-protected POST removes owned records atomically, cancels generation ownership, and removes only the canonical set directory after commit. Late workers cannot recreate the set. File failures retain a durable PendingFileDeletion marker with a library retry button; pending cleanup blocks backup restoration of the same identity. A fresh PDF import uses a new UUID and new Anki identities. Downloads, backups, and source PDFs outside the managed directory are kept.
- Manual source crops: one rectangle per basic/cloze/reverse note, selected by dragging or pixel coordinates on the note's immutable source page. A checkbox places it on the question too; otherwise it appears with the answer. Reverse notes share the crop across both directions. Unsaved previews validate/render it without saving or inference. Coordinates and placement are retained with revisions and backups (introduced in format 6). Bounded PNG crops are reconstructed from the source image with the existing Pillow dependency; exports bundle the crop and complete source slide. Crop edits/removal preserve note identities. Create a manual draft before attaching its crop. This does not implement image occlusion or diagram interpretation.
- The app is now called Recalloom, a name chosen with the user's delegated approval. Public UI and setup documentation use the new name. Historical research filenames, backup format markers, Anki note type names/IDs, media names, and SLIDES_* settings remain compatible with existing work.
- Codex connection screen: safe status detection, reuse of an existing ChatGPT sign-in, and a CSRF-protected Connect Codex button that starts the native CLI's official browser login. The page polls until sign-in finishes. Pending attempts are deduplicated, cancellable, and limited to ten minutes; stopping an attempt never invokes logout. Missing installation, API-key mode, and failures have distinct messages. Passwords and authentication files are not read or copied; raw CLI status output is neither displayed nor persisted. This manager assumes the supported single-process local server.
- Learning focus: Balanced, Core knowledge, Understanding, Application. Format: any nonempty combination of Basic Q/A, Cloze, and Basic + reverse. Defaults remain Balanced and Basic Q/A; each lecture reuses its last AI run's choices. Both choices reach generation/downloaded prompts and are retained on resume and backup. Application requests only source-supported methods/examples. No live quality comparison was run.
- Simple cloze: flat blanks numbered 1–20, optional hints, repeated numbers grouped on one card, optional extra explanation, manual text-selection helper, typed generation/JSON validation, and escaped previews. Existing note types and the set of cloze numbers stay fixed during edits to preserve Anki identities. The Card model remains the stored note; study_card_count derives its actual review-card count.
- Review-card budgets: each basic note counts as one, each reverse note as two, and each cloze note as its number of distinct blanks. Whole candidates that exceed the remaining allowance are skipped without suppressing smaller valid candidates. Reverse-only generation defaults to at least two cards and rejects a one-card ceiling before starting a worker. Batch allocation reserves room for complete pairs; odd ceilings can leave one slot unused. Runs retain both notes added and review cards added; library/export counts reflect actual review cards. Migration 0010 only extends format choices/length and preserves existing notes and run counts.
- Previews: manual/editor POST previews check unsaved text without saving or inference. Each question can reveal its answer. A paginated Preview export shows only accepted saved notes, their cards, edit links, and source-slide links. These are content previews, not an Anki scheduler.
- PDF upload: signature check, 25 MB/100-page limits, native text extraction and source rendering in a subprocess with a timeout. Identical uploads reuse the existing lecture. No-text pages are flagged.
- Lecture library and responsive editor with source viewer, manual cards, accept/set-aside, quick Accept & next, persistent edits, optimistic version checks, and revision history.
- Local CLI generation: existing authentication, explicit text-sharing consent, normally three-page batches, five-minute per-batch timeout, progress, cancellation, and preservation of completed batches. Codex discovery includes the VS Code extension; Claude discovery supports its native installation/current npm native executable. SLIDES_CLAUDE_BINARY can override discovery, alongside the existing Codex override. Shell wrappers are rejected.
- Reasoning dropdown: recognized values are CLI default, None, Minimal, Low, Medium, High, Extra high, and Max, plus Kimi's Thinking off/on, restricted to the selected model's reported support. New lectures start with Low when supported, including after first-run discovery; existing lectures reuse their last run. Explicit Codex effort uses model_reasoning_effort, Claude uses --effort, and Kimi uses ACP thinking config. CLI default omits the override and does not establish the effective level of historical runs. No Ultra/subagent workflow is exposed.
- Compact generation: new runs default to ceil(selected readable pages / 2) new cards, with a custom 1–500 ceiling. The prompt prioritizes concepts/methods and avoids logistics/repeated numerical examples. Application-side limits apply after validation, logistics filtering, and exact deduplication. Budgets carry forward unused room and reserve room for later pages; small limits widen batches. Runs retain their limit and filter/overflow counts across resume and backups. The download-prompt route uses the same limit.
- New generation sends up to 200 recent existing questions as untrusted context to discourage repeated concepts. Consent and README describe this additional data. Old runs with no saved limit do not send existing questions. Exact deduplication also recognizes the current text of edited questions.
- A conservative English/German local filter removes clear exam/course logistics from generated candidates. Existing untouched drafts can be set aside with a local POST action, retaining IDs and revisions. Accepted/edited cards and restored drafts are protected.
- Generation recovery: invalid individual drafts are retained as visible skipped-draft details while valid drafts and later batches continue. Strict source validation remains in place. Resume continues unprocessed pages of a failed/cancelled run; attempt tokens prevent a cancelled worker from writing late results into a resumed run. Repeated resume submissions do not start duplicate workers.
- Alternative generation: download a source-text prompt and import JSON drafts from an existing chat. Validation checks page membership and an exact supporting excerpt. Cards remain drafts for human checking.
- Normalized exact-question deduplication preserves existing edits. Paraphrased duplicates still need manual review.
- Anki export: accepted basic Q/A, cloze, and reverse notes, stable GUIDs/model/deck identity, escaped text, bundled source PNGs, and monotonic modification values for same-second edits. Reverse notes use a separate model (1890487185) with fixed forward/reverse ordinals; existing basic/cloze models are unchanged. Both answers include source evidence. A separate question-image field supports a crop on both reverse questions without revealing the opposite text or full source page.
- Per-lecture ZIP backup/restore: PDF, source text/images, all card states and IDs, edit revisions/timestamps, and generation metadata. Restores refuse existing lectures, reject arbitrary/duplicate paths and corrupt assets, validate record structure, and roll back on failure.
- Backup format 8 supports reverse notes and all format combinations, retaining the version-7 fields for requested model, provider/run settings, source crops/revisions, note types, focus, review-card counters, reasoning, ceilings, selection counts, and skipped details. Formats 1–7 remain readable; 1–5 have no crops and 1–4 restore as basic notes. Older application builds cannot read version-8 backups. Missing historical model/effort fields restore as CLI default. Restoration needs no CLI credentials or model metadata. Worker tokens are transient process ownership and are recreated on restore.
- Synthetic sample: three text slides and one image-only page, plus five hand-written drafts. The sample button does not call a model.
- Loopback-only middleware, CSRF protection, restrictive content security policy, local frontend assets, ignored private data, and pinned runtime/development requirements.

## Limits to preserve in communication

- Personal alpha, not beta/public-release ready. Full gates remain in MVP_BUILD_PLAN.md.
- The chosen CLI still needs installation on each machine; connection screens are not installers. README includes a pinned local Gemini/Kimi npm install, and these packages are already present in this working copy's ignored data/clis. Saved sign-in/metadata do not verify allowance or entitlement. Gemini status is a completion marker, not live token validation. Claude/Gemini/Kimi completed login and generation remain unverified with real accounts. Closing the app interrupts status tracking; after restarting, recheck the connection. CLI protocol changes may require adapter updates; refresh models after CLI/account changes.
- Native-text PDFs, basic Q/A, simple cloze, opt-in Basic + reverse, and one manual source crop per note. No OCR, diagram interpretation, image occlusion, PPTX, Anki import, scheduler, accounts, payments, native apps, or mobile sync. Existing note types cannot be changed through edits; automatic conversion of existing notes to reverse cards is not implemented.
- An excerpt matching a page does not establish correctness. No real lecture quality/time-saving benchmark exists.
- The compact and reverse-format prompts have only offline provider-boundary tests so far; card quality and allowance savings are unmeasured. Selection is prioritized within batches, not globally across the lecture. Reverse pairs always cost two review cards and may be inappropriate for many lecture facts. Logistics rules are deliberately narrow and can miss paraphrases. The stored note count includes Set aside cards.
- The responsive UI remains local to the desktop; another device cannot connect.
- Generation adds drafts; it does not automatically revise accepted notes. Resume preserves saved batches. Skipped-draft details are historical, not automatically resolved by later attempts; recreate corrected cards manually or select those pages for generation again. Manual JSON imports still fail atomically on any invalid draft.
- Exports are one-way additions/updates. Setting a card aside or deleting its set does not delete an earlier Anki copy. Reimporting slides after set deletion creates new identities; restore a backup to recover the original identities instead. Backups do not contain Anki review history.
- Restore intentionally refuses existing lectures. Use a different SLIDES_DATA_DIR to inspect an older backup. Limits: 200 MB uncompressed, 100 pages, 10,000 cards, 1,000 generation records, and 1,000 revisions per card.
- Parser isolation is a subprocess plus input/render/time limits, not a hardened public upload service.
